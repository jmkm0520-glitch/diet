# 프로젝트를 5분 만에 이해하기

[← 학습 가이드 목차](./README.md)

## 이 문서에서 답할 질문

> 사용자가 식단과 체중을 기록할 때 이 프로젝트의 각 부분은 무슨 일을 하는가?

「오늘도 가볍게」는 날짜별 체중과 아침·점심·저녁·간식을 기록하는 웹 애플리케이션이다. 사용자는
이메일 인증을 거쳐 회원가입하고 로그인한 뒤 기록을 저장할 수 있다. 저장한 기록은 날짜별 화면과
달력에서 다시 확인할 수 있다.

이 문서에서는 각 기술의 자세한 작동 원리를 다루지 않는다. 먼저 전체 구조와 역할만 살펴본다.

## 먼저 기억할 한 문장

> 사용자가 화면에서 행동하면 프론트엔드가 백엔드에 요청하고, 백엔드가 사용자와 입력값을 확인한
> 뒤 Supabase에서 데이터를 저장하거나 조회하며, 그 결과가 다시 화면에 표시된다.

## 프로젝트를 구성하는 다섯 영역

| 영역 | 이 프로젝트에서 하는 일 | 실제 위치·서비스 |
| --- | --- | --- |
| 도메인·DNS | `https://www.food-broccoli.shop`을 Vercel에 연결 | 가비아의 A·CNAME 레코드 |
| 프론트엔드 | 화면을 보여주고 입력을 받음 | `src/`, React, Next.js |
| 백엔드 | 요청과 사용자를 검사하고 저장을 지시함 | `api/`, Python |
| 데이터베이스·인증 | 회원과 식단·체중 데이터를 관리함 | Supabase |
| 배포 환경 | 프론트엔드와 백엔드를 인터넷에서 실행함 | Vercel |

### 도메인·DNS

이 프로젝트의 대표 사이트 주소는 `https://www.food-broccoli.shop`이다. 사용자는 숫자로 된
서버 주소 대신 이 도메인을 브라우저에 입력해 사이트에 접속한다. 가비아에서 관리하는 A·CNAME
레코드가 도메인이 찾아갈 Vercel 배포를 알려 주고, 실제 화면과 API는 Vercel에서 실행된다.

### 프론트엔드

프론트엔드는 사용자가 브라우저에서 직접 보고 조작하는 영역이다. 날짜 선택, 체중·식단 입력,
저장 버튼, 달력 등이 여기에 속한다. 이 프로젝트는 프론트엔드를 구현하기 위해 React와 Next.js를
사용하며 관련 코드는 `src/`에 있다.

### 백엔드

백엔드는 프론트엔드가 보낸 요청을 받아 로그인한 사용자인지와 입력값이 올바른지 확인한다. 확인을
통과하면 Supabase에 데이터를 조회하거나 저장하도록 지시한다. 이 프로젝트의 백엔드는 `api/`의
Python 코드다.

### 데이터베이스·인증

Supabase는 회원가입과 로그인을 처리하는 Auth, 회원·식단·체중 데이터를 보관하는 PostgreSQL을
제공한다. 이 프로젝트에서는 주요 데이터 요청이 Python 백엔드를 거쳐 Supabase로 전달된다.

### 배포 환경

Vercel은 `src/`의 프론트엔드와 `api/`의 Python 백엔드를 인터넷에서 사용할 수 있도록 배포하고
실행한다. 사용자의 식단과 체중 같은 영구 데이터는 Vercel이 아니라 Supabase에 보관된다.

## 한눈에 보는 프로젝트 지도

```text
사용자 브라우저
  ↓ https://www.food-broccoli.shop
  ↓ 가비아에서 관리하는 도메인·DNS
Vercel
  ├─ Next.js·React 프론트엔드 (`src/`)
  └─ Python 백엔드 API (`api/`)
       ↓
Supabase
  ├─ Auth: 회원가입과 로그인
  └─ PostgreSQL: 회원·식단·체중 데이터
```

가비아는 사용자의 요청을 처리하거나 화면을 제공하는 서버가 아니다. 가비아에서 관리하는 DNS
레코드는 도메인이 찾아갈 Vercel 주소를 알려준다. 실제 화면과 백엔드는 Vercel에서 실행된다.

## 체중을 저장할 때 일어나는 일

전체 구조를 사용자의 행동에 맞춰 보면 다음과 같다.

1. 사용자가 화면에 체중을 입력하고 저장 버튼을 누른다.
2. 프론트엔드가 백엔드에 체중 저장을 요청한다.
3. 백엔드가 로그인한 사용자와 입력값을 확인한다.
4. 백엔드가 Supabase 데이터베이스에 체중을 저장한다.
5. 프론트엔드가 저장 결과를 받아 화면에 표시한다.

지금은 이 순서만 기억하면 된다. 각 단계가 사용하는 통신 방식, 코드, 로그인 정보, 데이터 구조는
뒤의 문서에서 하나씩 확대해서 살펴본다.

## 프로젝트 폴더를 세 부분으로 보기

- [`src/`](../../src/): 화면을 보여주고 사용자의 행동을 처리하는 프론트엔드
- [`api/`](../../api/): 요청을 검사하고 데이터를 처리하는 Python 백엔드
- [`supabase/migrations/`](../../supabase/migrations/): 데이터베이스 구조가 어떻게 변경됐는지 기록한 파일

처음부터 모든 파일을 읽을 필요는 없다. 화면 문제는 `src/`, 요청 처리 문제는 `api/`, 데이터 구조
문제는 `supabase/migrations/`에서 시작하면 된다.

## 자주 생기는 오해

### 프론트엔드와 React는 같은 뜻인가?

아니다. 프론트엔드는 사용자가 보고 조작하는 영역이고, React는 이 프로젝트가 그 영역을 만들기
위해 선택한 도구다.

### 가비아에서 애플리케이션이 실행되는가?

아니다. 가비아에서는 도메인과 DNS 레코드를 관리한다. 프론트엔드와 백엔드는 Vercel에서 실행된다.

### Vercel에 식단과 체중 데이터가 보관되는가?

아니다. Vercel은 애플리케이션을 실행하고, 식단과 체중 같은 영구 데이터는 Supabase PostgreSQL에
보관한다.

### Supabase가 사용자 화면을 그리는가?

아니다. 사용자 화면은 `src/`의 프론트엔드가 담당한다. Supabase는 로그인과 데이터 보관을 담당한다.
