# 포트폴리오 재료 노트

> 포트폴리오를 쓸 때 그대로 옮겨 붙일 재료를 작업하면서 쌓아 두는 파일.
> 형식은 신경 쓰지 말고, **왜 고쳤는지와 어떻게 확인했는지**를 남기는 것이 목적이다.
> 코드는 커밋에 남지만 판단 근거는 남지 않는다. 나중에 재구성이 안 되는 건 이쪽이다.

작성 시작: 2026-08-20

---

## 쓰는 법

문제 하나당 블록 하나. 다 채우려 하지 말고 **기억 안 나면 못 쓰는 것**만 적으면 된다.

```
### 제목
- 증상:  (사용자가 본 것)
- 원인:  (진짜 이유. "왜 그렇게 돼 있었나"까지)
- 해결:  (무엇을 바꿨나 + 커밋)
- 확인:  (고쳐진 걸 어떻게 증명했나)
- 한 줄: (포트폴리오에 넣을 요약)
```

스크린샷은 `docs/images/`에 `before-*.png` / `after-*.png`로 저장.

## 2026-08-20

### 1. 새로고침하면 없던 "공복 / 자유식" 기록이 되살아남

- **증상**: 아침·점심 칸에 입력한 적 없는 `공복`이 자유식(빨강)으로 저장되어 있고, 새로고침할 때마다 다시 나타남.
- **원인**: `MealCard.saveMeal()`에 `foodInput.trim() || "공복"`이 있었다. 빈 칸으로 저장을 누르면 코드가 `공복`을
  대신 채워 **DB에 진짜 행을 만들었다.** 자동 생성이 아니라 한 번 저장된 실제 기록이라 계속 되살아난 것.
- **해결**: 빈 값 처리 정책을 `getMealSaveInput()`으로 분리. 최종 정책은 **빈 칸 = `공복` + 클린식 자동 저장**이며,
  자유식을 눌러 둔 상태여도 클린식으로 저장한다. (`공복`을 자유식으로 기록하는 조합 자체를 없앰) — `830e14e`
- **확인**: 배포된 프로덕션 JS 번들을 직접 내려받아 문자열을 검사했다. 빌드 성공 표시만 믿지 않고
  `공복` 자동 대체 코드가 실제로 사라졌는지 / 새 코드가 들어갔는지를 확인.
- **한 줄**: 화면에 보이는 증상("자동으로 생긴다")과 실제 원인("한 번 저장된 진짜 데이터")이 달랐던 사례.
  코드를 고치기 전에 **데이터가 어디서 왔는지부터 확인**해야 했다.

> 이 항목은 Before/After 표에 쓰기 좋다.
> Before: 빈 칸 저장 → 의미 불명의 `공복 / 자유식` 기록이 남음
> After: 빈 칸 저장 → `공복 / 클린식`으로 일관되게 저장, 수정 버튼 없이도 바로 수정 가능

### 2. 햄버거 메뉴 버튼이 스크롤을 따라다님 (5번째 시도에서 해결)

- **증상**: 스크롤해도 메뉴 버튼만 화면에 떠 있어 본문 위를 덮음.
- **원인**: 버튼이 `position: fixed`(뷰포트 고정)였다. 이전에 네 번의 수정 시도가 있었는데
  (`c5f41b0`, `720a087`, `7962ee3`, `cfffe4e`) 모두 **fixed를 유지한 채 좌표만 조정**하거나
  헤더를 `sticky`로 만들어 따라가게 하려는 방식이었다. 헤더 sticky는 부모 `.main`에 `overflow: hidden`이
  걸려 있어 애초에 동작하지 않았다.
- **해결**: 좌표를 고치는 대신 **버튼을 헤더 DOM 안으로 옮겼다.** 메뉴 상태를 React Context로 공유하고
  `SiteMenuButton`을 분리해 세 페이지 헤더가 `오늘 기록 / 캘린더` 탭 옆에 직접 렌더하도록 변경. — `42a576d`
- **확인**: 배포된 CSS를 내려받아 `.menuButton`에서 `position:fixed`가 사라지고
  `.headerActions` 플렉스 컨테이너가 생긴 것을 확인.
- **한 줄**: 같은 버그를 네 번 고치려다 실패한 이유는 **증상(좌표)을 고치고 원인(배치 방식)을 안 고쳐서**였다.
  좌표 조정에서 구조 변경으로 접근을 바꾸자 한 번에 끝났다.

> 곁가지로 배운 것: 버튼이 다른 컴포넌트 트리에서 렌더되면서 `ref`를 Context로 넘기니
> `react-hooks/refs` 린트에 걸렸다. 포커스 복원을 `ref` → `id` 조회 방식으로 바꿔 해결.

### 3. 달력 아이콘을 눌러도 달력이 안 뜸

- **증상**: 날짜 선택 타일을 클릭해도 아무 일도 일어나지 않음.
- **원인**: 그 타일은 버튼이 아니라 `<input type="date">`를 `opacity: 0`으로 아이콘 위에 덮어놓은 것이었다.
  **크롬은 날짜 입력창의 자체 달력 인디케이터를 눌렀을 때만 달력을 연다.** 그 인디케이터가 투명 처리로
  안 보이니 클릭이 날짜 텍스트 영역에 떨어져 포커스만 됐다.
- **해결**: 클릭 시 `HTMLInputElement.showPicker()`를 직접 호출. API가 없거나 브라우저가 거부하면
  기존 동작(포커스 후 직접 입력)이 남도록 `try/catch`. — `fc97009`
- **한 줄**: "커스텀 디자인을 위해 네이티브 컨트롤을 투명하게 덮는" 흔한 패턴의 부작용.
  보이는 것과 클릭 대상이 어긋나면 브라우저 기본 동작이 깨진다.

### 4. 되돌린 작업 — 끼니별 삭제 버튼

- 1번 문제를 해결하는 과정에서 "잘못 저장된 한 끼만 지우는" 기능을 만들었다 (`0df358c`).
  API에 `meal` 파라미터 추가 + 카드마다 삭제 버튼.
- 검토 후 **UI를 단순하게 유지하기로 하고 전부 되돌렸다** (`bbbe427`). 카드는 `저장 → 수정` 두 상태만 유지.
- 현재 잘못 저장된 기록을 지우는 방법은 하루 전체를 지우는 `식단 초기화`뿐이다.
- **한 줄**: 기능을 넣는 판단만큼 **빼는 판단**도 기록해 둘 가치가 있다. 되돌린 이유가 남지 않으면
  나중에 같은 기능을 또 만들게 된다.
